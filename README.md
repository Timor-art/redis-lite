# Redis Lite

一个本地启动、通过浏览器使用的轻量 Redis 只读工具。原生 HTML/CSS/JavaScript + Node.js HTTP 服务，运行依赖只有 Redis 官方基础客户端 `@redis/client`，无需前端构建或额外数据库。

## 启动

需要 Node.js 22 或更新版本。

```sh
cd redis-lite
npm ci
npm start
```

打开 <http://127.0.0.1:6380>。当前目录已经安装依赖，直接 `npm start` 即可。macOS 也可双击 `启动 Redis Lite.command`；脚本首次运行会安装缺失的依赖。

### macOS 一键启动

推荐使用 `Redis Lite.app`，不需要每次打开终端：

1. 在 GitHub 仓库页面点击 `Code` → `Download ZIP`，下载并解压项目。
2. 打开解压后的 `redis-lite` 文件夹，确认 `Redis Lite.app`、`server.mjs`、`package.json` 在同一层级关系中。不要把 `.app` 单独拖到其他位置。
3. 双击 `Redis Lite.app`。首次启动会自动执行依赖安装，可能需要等待几秒；完成后会自动打开浏览器页面。
4. 在页面中点击“连接 Redis”，填写 Redis 主机、端口、用户名、密码和数据库编号，然后测试连接。
5. 以后使用时直接再次双击 `Redis Lite.app`。如果服务已经运行，它只会打开浏览器，不会重复启动服务。
6. 使用结束后，双击同一目录中的 `停止 Redis Lite.command` 停止本地服务。

如果 macOS 提示无法打开应用，请右键 `Redis Lite.app`，选择“打开”，再确认一次。若首次启动提示依赖安装失败，请确认电脑已安装 Node.js 22 或更新版本，并检查网络后重新双击。服务默认使用 `http://127.0.0.1:6380`；若端口已占用，可以改用命令行方式启动：`PORT=6381 npm start`，然后打开 `http://127.0.0.1:6381`。

按 `Ctrl+C` 停止。端口被占用时：

```sh
PORT=6381 npm start
```

## 使用

1. 点击“新建连接”，输入主机、端口、用户名/密码、数据库编号，可选择 TLS。
2. 点击“测试并连接”。通过实际连接和 PING 后才进入数据浏览。
3. 搜索框支持 Redis glob 模式，如 `user:*`、`cache:product:?`，输入后按回车。空输入扫描所有 Key。
4. 点击 Key 查看类型、TTL、字节数/成员数和内容。“永不过期”对应 TTL = -1。
5. 顶部数据库下拉框支持连接后直接切换 DB，复用当前认证，不需要重新输入密码。切换成功清空旧列表和详情，重新扫描；失败保留原数据库。优先读取实例配置中的数据库数量，权限不允许时列出常用 DB 0–15，并提供“其他数据库”手动输入，最终由 Redis 验证编号。演示模式 DB 0 有样例，其余数据库为空。
6. 点击“继续扫描”加载下一批 Key；集合详情通过“读取下一批”翻页，刷新回到第一批。
7. 可以先点击“体验演示”，体验内置样例。演示模式不连接 Redis，有明确的示例数据提示。

支持 String / Hash / List / Set / ZSet，提供 JSON 格式化、原始内容展示、复制当前页、只读浏览、连接配置管理和响应式布局。

## 连接和数据边界

- 仅监听 `127.0.0.1`，校验 Host / Origin，拒绝跨站请求，不向外部服务发送 Redis 数据。
- 只提供固定读取接口和连接级数据库切换（SELECT），没有写入、删除、任意命令或脚本执行入口。
- 主机、端口、用户名、数据库和 TLS 开关保存在浏览器 localStorage，最多保存 20 个配置；密码不写入配置、磁盘或日志。密码仅随本机请求提交并由连接客户端在内存中持有，断开后释放客户端引用。
- 同一浏览器同源标签页共享连接会话；每个会话只有一个活动连接。30 分钟无请求后释放；关闭页面不会立即释放，点击“断开连接”可立即释放。
- 连接超时约 4 秒，单次 Redis 命令上限 5 秒，超时关闭连接，需要重新连接。
- TLS 使用系统默认信任链并验证证书；暂不支持自定义 CA、客户端证书和跳过证书验证。
- 目前支持单机 Redis，不支持 Cluster、Sentinel、SSH 隧道、Stream/模块类型内容、编辑和批量操作。
- 以 UTF-8 文本为目标，暂不支持二进制 Key 的无损浏览和二进制值的十六进制查看。

## 大数据读取约定

- Key 使用 `SCAN MATCH COUNT 100`；COUNT 只是提示，返回数量不固定，空批次不表示完成。游标回到 0 才完成。前端对已加载 Key 去重，达到 5000 条后停止继续扫描，要求缩小搜索范围（最后一批可能超过阈值）。
- String 用 `GETRANGE` 读取前 16 KiB，并展示真实字节长度。截断内容有提示，复制也仅复制预览。
- List/ZSet 每次最多读取 100 项。Hash/Set 使用 HSCAN/SSCAN COUNT 100，每批成员数不保证固定；每个成员值最多显示 16 KiB。
- 集合详情显示当前批次，避免持续累积大量内容。扫描期间数据变化可能导致重复、遗漏或位置变化，元信息与值不是事务快照。
- HTTP JSON 响应上限为 2 MiB，超过时明确报错，不静默丢弃成员。集合成员在 Redis 协议层仍可能完整传输到本地服务，预览截断不是网络/内存硬上限；特别大的集合成员建议使用专用客户端。
- 不自动全量扫描、不自动刷新、不读取全部 Key 的值。数据只按用户操作请求。

## 项目结构

```text
server.mjs       本地 HTTP、会话连接、Redis 读取与参数边界
demo.mjs        与真实连接隔离的演示数据
public/
  index.html     页面和连接表单
  style.css      桌面/窄屏布局
  app.js         连接、搜索和详情交互
test/app.test.mjs  HTTP 边界及独立 Redis 集成测试
```

实现保持三类职责：连接与数据访问、演示数据、界面展示。公用请求、超时、错误和预览处理复用；不引入框架、插件体系或额外持久层。

## 测试

```sh
npm test
```

默认运行本地接口与演示流程测试。若提供 Redis 可执行文件路径，还会启动一个随机端口、禁用持久化的独立 Redis，测试后自动停止，不连接已有实例：

```sh
REDIS_SERVER=/absolute/path/to/redis-server npm test
```

覆盖 Host/Origin 拒绝策略、会话隔离、连接后 DB 切换与隔离、切换失败保留原 DB、无 CONFIG 权限时的降级、五种类型、连接失败保留原连接、认证、数据库切换、SCAN 多批游标、大字符串截断、List 翻页、ZSet 分值、过期 Key、空 Key 和不支持的类型。
